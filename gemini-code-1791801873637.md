# Vibe Coding Guide — StockSync Retail Inventory & POS Billing App
This guide contains a series of **9 sequential prompts** designed for students to build a full-stack, real-time inventory management and Point-of-Sale (POS) billing web application using Next.js, Prisma (SQLite), NextAuth.js, and Razorpay[cite: 1, 2, 3, 4].

By feeding these prompts to an AI coding assistant step-by-step, students can construct the architecture, schema, transactional sales workflow, stock depletion logic, and interactive barcode/receipt interfaces[cite: 1, 2, 3, 4].

---

## Technical Architecture & Setup Rules

To ensure students avoid common build failures and runtime bugs, the prompts enforce these standard guardrails:
1. **Windows C++ Compiler Restrictions**: Downgrade Prisma to version `6` (`^6.4.0`) to run the built-in Rust query engine, bypassing native C++ driver adapters (like `better-sqlite3`) that require Visual Studio C++ build tools on Windows[cite: 1, 2, 3, 4].
2. **Lucide React CASING & Icons**: Use `lucide-react` version `0.475.0` to avoid broken exports and retain system/brand icons[cite: 1, 2, 3, 4].
3. **styled-jsx inside Server Components**: Keep Server Components pure; extract all POS and dashboard styles to external CSS modules or dedicated stylesheets to eliminate hydration conflicts[cite: 1, 2, 3, 4].
4. **React Hydration Mismatch**: Dynamic browser calculations, timestamps, and client randomizers must be deferred using `useEffect` so server-rendered HTML matches the client render[cite: 1, 2, 3, 4].
5. **Keyless Payments (Sandbox Simulator)**: Allow end-to-end checkout testing locally without active Razorpay API keys using a custom sandbox modal and API signature bypass[cite: 1, 2, 3, 4].
